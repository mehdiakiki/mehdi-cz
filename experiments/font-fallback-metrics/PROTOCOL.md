# PERF-056 preregistered protocol

Date locked: 2026-09-15, before deriving or timing a replacement fallback.

## Question

Can a route-informed Arial metric override remove the small desktop font-swap
layout shifts without delaying LCP, changing the final Space Grotesk rendering,
or suppressing the branded font on a cold connection?

## Existing attribution and baseline

PERF-050 already provides the causal intervention. In fresh desktop contexts,
priming only `/_next/static/media/5a0c43ffa288c21a-s.p.woff2` made every observed
shift disappear while leaving CSS cold. Cold runs recorded CLS from 0.0001602 to
0.0022707, and their source rectangles were text whose position or width changed
when Space Grotesk replaced its fallback. PERF-056 will not repeat that
attribution as though it were a new result.

The fixed browser artifact is `.next-perf050`, generated by Next.js 16.3.4. Its
global stylesheet is `ebc471532293f512.css`. The control is Next's generated
Arial fallback:

```css
ascent-override: 88.78%;
descent-override: 26.34%;
line-gap-override: 0%;
size-adjust: 110.84%;
```

The framework derived that size adjustment from a fixed Latin frequency string,
not this site's rendered copy. The experiment keeps the production HTML,
JavaScript, primary font bytes, preload, cache policy, and `font-display: swap`
unchanged. Matched proxies may replace only the four fallback descriptor values
in the global CSS response.

## Candidate derivation

Derive one candidate before looking at candidate CLS or LCP:

1. In unthrottled Chromium at 1440 x 900, load Space Grotesk and collect visible
   text runs from the five fixed routes: home, writing index, prose article, code
   article, and Rust Failure Atlas. Ignore script, style, SVG, hidden, zero-area,
   monospace, and icon-only nodes. Deduplicate identical `(text, font size,
   weight, letter spacing)` specimens while retaining occurrence counts.
2. Measure each specimen's single-line advance in the loaded primary face and in
   unadjusted local Arial. Select the `size-adjust` scalar that minimizes the
   occurrence-weighted sum of squared advance error. Round once to two decimals,
   matching Next's generated CSS precision.
3. Preserve Space Grotesk's effective ascent, descent, and line gap. Recalculate
   each override by dividing the control's effective metric
   (`control override x control size-adjust`) by the candidate size adjustment,
   then round to two decimals.
4. Record the complete corpus, formula, control error, candidate error, hashes,
   and descriptors. Advance the candidate only if weighted RMSE improves by at
   least 20%, its maximum absolute advance error does not grow, and no specimen
   changes line count in its real container.

This derivation intentionally tunes one global face rather than assigning a
different fallback per route. No second candidate may be selected after seeing
browser timing. If the deterministic arm fails, report the limit of a single
Arial scale and stop.

## Browser comparison

For an eligible candidate, use Chromium with fresh browser contexts, 150 ms
latency, 1.6 Mbps downstream, 750 kbps upstream, and 4x CPU slowdown. Test both
390 x 844/DPR 2.75 mobile and 1440 x 900/DPR 1 desktop. Visit the same five
routes, run eight matched repetitions per profile and route, and alternate proxy
order within each repetition. Do not overlap timing with builds, screenshots,
coverage, or other heavy workloads. Retain individual observations and paired
differences.

Observe LCP, FCP, load, layout-shift entries and source rectangles, font request
timing/bytes, `document.fonts` events, heading presence, and runtime exceptions.
Each sample ends 700 ms after `load`, matching PERF-050. Confirm that the font is
cold, requested once, completes, and becomes the rendered face in every arm.

## Fidelity and retention gates

The candidate is retained only if all gates pass:

- every desktop route's candidate median CLS is at least 75% below its matched
  control and no candidate observation exceeds 0.00025;
- all mobile observations remain CLS zero;
- no profile/route has a paired-median LCP regression greater than 32 ms or 3%,
  whichever allowance is larger, and the deterministic bootstrap interval does
  not establish a regression beyond that allowance;
- after `document.fonts.ready`, candidate and control screenshots, text wrapping,
  and sampled computed typography are exact because both render the same primary
  font;
- while the primary response is deliberately held, the candidate has no extra
  wrapping or clipped/overflowing text and its fallback-to-primary geometry error
  is no worse than the control on any route;
- transferred resource count and font bytes are unchanged, with no console,
  preload, hydration, or accessibility regression; and
- a fresh production build materializes the same candidate descriptors from
  source and passes the repository's existing performance/static checks.

An exact zero-CLS result is preferred but is not required: the starting values
are already far below the 0.1 Core Web Vitals boundary, so a fragile or merely
cosmetic change is not a win.

## Excluded delivery arms

`font-display: optional` is excluded because it can avoid a swap by leaving the
cold visit in the fallback face, violating the branded-font completion contract.
`block` is excluded because hiding primary page text until the font arrives is
not an acceptable LCP strategy. `fallback` is not tested unless the metric arm
cannot be formed and a separately preregistered timing model predicts a useful
swap-window change; the current font completes inside the existing cold-load
trace, so changing the keyword alone has no demonstrated mechanism for improving
both completion and layout.

## Decision rule

Retain the smallest source change only when the deterministic derivation and all
browser, fidelity, and build gates pass. Otherwise keep Next's generated fallback
and document PERF-056 as rejected or inconclusive. Lab measurements do not imply
a production Core Web Vitals improvement.
