A programmer can know four languages and still apply the mental model of one language to all four. That is where interesting bugs appear.

This set uses Python, TypeScript, Go, and Java. They cover dynamic and static typing, garbage-collected runtimes, structural and nominal type systems, synchronous and asynchronous conventions, and different approaches to errors and cancellation. They are also widely used ecosystems: GitHub's 2025 data places TypeScript, Python, Java, and Go among its leading languages.

The goal is not syntax trivia. Each problem begins with a shared engineering idea and asks what that idea means in each language.

Like the [Rust set](/blog/ai-resistant-rust-interview-problems), "AI-resistant" means resistant to a memorized answer. It does not mean AI-proof. A public problem can be retrieved. The durable signal comes from changing the constraint and asking the engineer to verify the new answer.

## Problem 1: I copied it, so why did the original change?

Predict every output before running the examples.

### Python

```python
rows = [[]] * 3
rows[0].append("x")
print(rows)
```

The result is:

```text
[['x'], ['x'], ['x']]
```

List multiplication repeats references to the same inner list. It does not create three independent inner lists.

The repair expresses the allocation we intended:

```python
rows = [[] for _ in range(3)]
```

### TypeScript

```typescript
const original = { limits: { retries: 3 } }
const copy = { ...original }

copy.limits.retries = 0
console.log(original.limits.retries)
```

The result is `0`. Object spread creates a new outer object, but `limits` still refers to the same nested object.

There is no universal "deep copy" operation that preserves every JavaScript value and application invariant. `structuredClone` supports many built-in data types, but cloning may be the wrong model for class instances, functions, database entities, or intentionally shared objects. A strong answer first asks which parts must be independent.

### Go

```go
package main

import "fmt"

func main() {
    original := []int{1, 2, 3}
    copyOfSlice := original[:]
    copyOfSlice[0] = 9
    fmt.Println(original)
}
```

The result is `[9 2 3]`. Copying a slice copies its small descriptor. The two descriptors still point to the same backing array.

To copy the elements:

```go
copyOfSlice := append([]int(nil), original...)
```

Capacity still matters when appending. Two slices can share a backing array until one append forces a new allocation. The answer is not simply "slices are references"; the descriptor and backing array are separate parts of the model.

### Java

```java
var shared = new java.util.ArrayList<Integer>();
var rows = java.util.Collections.nCopies(3, shared);

rows.get(0).add(1);
System.out.println(rows);
```

The result is `[[1], [1], [1]]`. `nCopies` creates an immutable list containing the same element reference repeatedly. The outer list cannot be structurally modified, but the shared inner list remains mutable.

### What to ask next

The first answer is only the warm-up. Change the requirement:

> The nested value is intentionally shared for reads. Only the first write should create an independent copy.

Now eager deep copying is wasteful. The candidate must discuss copy-on-write, ownership, concurrency, and how callers learn whether they have a snapshot or a live view.

## Problem 2: cancellation is a request, not a time machine

An HTTP request is cancelled. Does the database or background work stop?

The weak cross-language answer is "yes, because the task was cancelled." In all four ecosystems, cancellation must reach the operation that can cooperate with it.

### Python

`asyncio` cancellation normally raises `CancelledError` at an await point. Cleanup belongs in `finally`, and code should not accidentally swallow cancellation.

```python
async def worker():
    resource = await acquire()
    try:
        return await use(resource)
    finally:
        await release(resource)
```

Code that performs blocking work outside the event loop, or starts an independent task and loses its handle, needs another cancellation design. Cancelling the parent coroutine does not rewind an external side effect that already happened.

### TypeScript

JavaScript promises do not have general cancellation semantics. Web and Node APIs may accept an `AbortSignal`, but the signal must be passed through every relevant layer.

```typescript
async function load(url: string, signal: AbortSignal) {
  const response = await fetch(url, { signal })
  return response.json()
}
```

Racing work against a rejected timeout promise does not stop the losing operation. It only stops waiting for it. If the work can mutate state, that difference is important.

### Go

Closing or cancelling a `context.Context` does not kill a goroutine. The goroutine or called API must observe `ctx.Done()` and return.

```go
select {
case result := <-results:
    return result, nil
case <-ctx.Done():
    return zero, ctx.Err()
}
```

If the producer can block forever while sending to `results`, the consumer returning may leak the producer. Buffering, ownership of channel closure, and a cancellation branch on the send side belong in the answer.

### Java

Thread interruption is cooperative. Blocking methods may throw `InterruptedException`. If code catches it but cannot propagate it, restoring the interrupted status is often necessary:

```java
try {
    return queue.take();
} catch (InterruptedException error) {
    Thread.currentThread().interrupt();
    throw new IllegalStateException("operation interrupted", error);
}
```

The correct policy depends on the API boundary. The important point is not to turn an interruption request into ordinary success or silently continue expensive work.

### What to ask next

Change the operation from a read to "charge a card, then record the receipt." Cancellation cannot undo the charge. The candidate now needs idempotency, reconciliation, and a state model—not a different cancellation primitive.

## Problem 3: the number fits until it crosses a boundary

The service receives this identifier in JSON:

```text
9007199254740993
```

Can every language read it, preserve it, and send it back unchanged?

### Python

Python integers have arbitrary precision, subject to available memory. Its standard JSON decoder can preserve this integer as an `int`. That does not guarantee the next system in the chain can.

### TypeScript

The ordinary JavaScript `number` type uses IEEE-754 double precision. `9007199254740993` is larger than `Number.MAX_SAFE_INTEGER`, so parsing it as a normal JSON number loses integer precision.

`bigint` can represent the value, but standard `JSON.stringify` does not serialize a `bigint` without a conversion strategy. External identifiers of this size are often safer as validated strings at the boundary.

### Go

Decoding into a typed `int64` can preserve this particular value. Decoding arbitrary JSON into `interface{}` with default `encoding/json` behaviour uses `float64` for numbers and can lose precision. `Decoder.UseNumber` or a typed structure changes the result.

The answer therefore depends on the target type, not only the language.

### Java

Java can preserve the value in a `long`, but JSON library configuration and target types still decide what actually happens. A value outside the signed 64-bit range needs `BigInteger` or a string representation.

### What to ask next

The identifier must be used as a database key, displayed unchanged, and compared across services owned by different teams. The best answer is usually a contract decision: encode opaque identifiers as strings, validate their grammar, and avoid arithmetic semantics entirely.

## Problem 4: a map key needs an identity policy

"Put this value in a map" sounds language-neutral. It is not.

### Python

A list cannot be a dictionary key because it is mutable and unhashable. A tuple can be a key only when its contents are also hashable. For user-defined objects, equality and hashing must remain consistent.

### TypeScript

Keys in `Map` can be objects, but object keys use identity. Two separately created `{ id: 1 }` objects are different keys. A plain object used as a dictionary normally coerces keys to strings; `Map` and `Record` are not interchangeable storage choices.

### Go

Go map keys must be comparable. Slices, maps, and functions cannot be map keys. An array can be a key when its element type is comparable, which sometimes provides a useful fixed-size value key.

### Java

`HashMap` depends on stable, consistent `equals` and `hashCode`. Mutating fields that participate in a key's hash after insertion can make the entry appear lost because lookup searches a different bucket.

### What to ask next

The key is a user record whose display name may change. Ask the candidate to define identity. A stable user ID and a changing presentation value should not be collapsed into one accidental equality rule.

This is the recurring lesson in the whole set: collection APIs force product decisions about identity, mutability, and time. Syntax is the small part.

## How I would score the discussion

I would not require perfect recall across four standard libraries. I would look for whether the engineer:

- says what they know and what they would verify;
- distinguishes a value, a reference, and a view;
- follows cancellation into the actual side effect;
- checks representation at system boundaries;
- defines identity before choosing a key;
- revises the solution when the constraint changes.

These habits transfer between languages. That is why the comparison is useful.
